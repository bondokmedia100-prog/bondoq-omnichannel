# نظام حلواني بندق متعدد القنوات

نقطة انطلاق عملية لمنصة دعم ومبيعات عربية RTL: واجهة Next.js، API بـ Express وTypeScript، PostgreSQL/Prisma، Redis/BullMQ، وSocket.IO للتحديثات الفورية.

## التشغيل باستخدام Docker

1. انسخ `.env.example` إلى `.env` وغيّر كلمات مرور الحسابات التجريبية و`JWT_SECRET` و`POSTGRES_PASSWORD` قبل أي نشر حقيقي.
2. من هذا المجلد شغّل `docker compose up --build`.
3. افتح `http://localhost:3000`.

عناوين الخدمة: الواجهة `http://localhost:3000`، الـ API `http://localhost:4000/api/health`، وWebhook واتساب على `/webhooks/kalemlywa` وMessenger على `/webhooks/meta`.

### التشغيل على Windows

1. ثبّت Docker Desktop لويندوز، وافتحه وانتظر حتى تظهر حالة التشغيل. يتطلب Docker Desktop تفعيل WSL 2 عادةً.
2. فك ضغط الحزمة إلى مجلد على الجهاز.
3. انقر مرتين على `START-WINDOWS.bat` وانتظر اكتمال البناء في المرة الأولى؛ يلزم اتصال بالإنترنت لتنزيل صور Docker.
4. ستفتح لوحة النظام في المتصفح على `http://localhost:3000`.
5. لإيقاف النظام مع الاحتفاظ ببياناته، انقر مرتين على `STOP-WINDOWS.bat`. لا تحذف مجلد Docker أو وحدات البيانات إذا أردت الاحتفاظ بالمحادثات.

لا يحتاج التشغيل المحلي إلى تثبيت Node.js أو PostgreSQL أو Redis على Windows؛ تشغّلها Docker Desktop داخل الحاويات. بيانات الدخول التجريبية المحلية موجودة أدناه، وهي للاختبار فقط. ربط WhatsApp الفعلي يتطلب إعداد بيانات المزود وعنوان Webhook عام؛ `localhost` وحده لا يستقبل Webhooks من الإنترنت.

المعاينة التفاعلية المنفصلة نموذج بصري ببيانات تجريبية، ولا تتصل بواجهة API أو تدخل ضمن خدمات النشر.

## حسابات التجربة

- المدير: `admin@bondoq.com` / `BondoqAdmin@2026`
- أحمد: `ahmed@bondoq.com` / `Agent@123`
- سارة: `sara@bondoq.com` / `Agent@123`
- محمود: `mahmoud@bondoq.com` / `Agent@123`

الحسابات التجريبية تُنشأ في `prisma/seed.ts`. غيّر كلمات مرور التجربة فورًا، ولا تستخدمها خارج بيئة محلية. كلمات المرور تُخزّن باستخدام bcrypt، ورمز JWT تجريبيًا صالح 12 ساعة.

## تطوير محلي دون Docker

1. شغّل PostgreSQL وRedis، واضبط `DATABASE_URL` و`REDIS_URL` في بيئة API.
2. داخل `apps/api`: نفّذ `npm install` ثم `npm run db:generate` و`npm run db:push` و`npm run db:seed` ثم `npm run dev`.
3. داخل `apps/web`: نفّذ `npm install` ثم `npm run dev`.

## قنوات الرسائل

- الوضع الافتراضي لواتساب هو محرك Baileys عبر QR: من «إعداد واتساب» في لوحة المدير ابدأ الاتصال، ثم امسح الرمز من WhatsApp ← الأجهزة المرتبطة ← ربط جهاز. تُرسل الرسائل والوسائط عبر الجلسة المرتبطة، وتصل الرسائل الواردة إلى CRM.
- Baileys مكتبة غير رسمية لواتساب ويب؛ ليست WhatsApp Business API، ولا تضمن Meta استمرارها أو قبولها، وقد يتعرض الحساب للقيود. يمكن الرجوع إلى KalemlyWA API من محدد الوضع دون حذف إعداداته.
- إعداد KalemlyWA الاحتياطي متاح للمدير من زر «إعداد واتساب». يدخل المدير authkey وappkey كلًّا على حدة، ويُخزّنان مشفّرين. يستخدم هذا الوضع `https://whatsapp.kalemly.com/api/send-message` ويستقبل الرسائل عبر `POST /webhooks/kalemlywa`. لوحة المدير تعرض رابط Webhook الكامل، بما فيه `?token=`؛ لا تحذف الرمز أو تشاركه علنًا. لا يحتاج API إلى Instance ID.
- تُحفظ جلسة Baileys في `WHATSAPP_AUTH_DIR` (الافتراضي `apps/api/data/whatsapp-auth` عند تشغيل API مباشرة). يوفر Docker Compose وحدة بيانات محلية باسم `whatsapp_auth`. يجب ربط مساحة تخزين دائمة بمسار `/data` في الاستضافة كي لا يلزم مسح QR بعد إعادة نشر الخدمة.
- يمكن للنظام اكتشاف المكالمة الواردة وعرضها للموظف أو المدير، ثم رفضها وإرسال رد نصي تلقائي. Baileys لا يستطيع الرد على المكالمة أو تمرير صوتها إلى المتصفح؛ هذه ليست ميزة اتصال صوتي فعلي.
- مساحة الموظف تدعم مكالمة صادرة كاملة من داخل النظام عبر WhatsApp Business Calling API وWebRTC، من دون WhatsApp Web. يلزم رقم Cloud API إيرلندي (+353)، تفعيل Calling على رقم الأعمال، حد إرسال يومي لا يقل عن 2,000 مستلم فريد وفق متطلبات Meta الحالية، اشتراك Meta في Webhook حقلي `calls` و`messages`، وموافقة العميل على الاتصال. يظل رقم مصر الحالي للمراسلات؛ المكالمة تظهر للعميل من الرقم الإيرلندي.
- عند استخدام Baileys، يرسل زر الاتصال رابطًا مؤقتًا عبر WhatsApp لفتح مكالمة WebRTC بين متصفح الموظف ومتصفح العميل؛ لا يتطلب Phone Number ID ولا ينقل الصوت داخل WhatsApp. يحتاج نطاق الواجهة `WEB_ORIGIN` إلى HTTPS، ويُنصح بإعداد `WEBRTC_TURN_URLS` و`WEBRTC_TURN_SHARED_SECRET` لتعمل المكالمات عبر شبكات NAT المقيدة.
- حفظ المفتاحين لا يرسل رسالة؛ اختبار الإرسال إجراء منفصل.
- إعداد Messenger متاح للمدير من زر «إعداد Messenger»؛ تُخزّن مفاتيح الصفحة وMeta مشفّرة ويمكن اختبار Page Access Token من الواجهة. سجّل `GET/POST /webhooks/meta` لدى Meta مع اشتراك أحداث الرسائل، وتظل نافذة الـ24 ساعة خاصة بـ Messenger.
- إعداد Telegram متاح للمدير من زر «إعداد Telegram»؛ تُخزّن بيانات البوت مشفّرة، ويمكن اختبارها وتسجيل `POST /webhooks/telegram` تلقائيًا باستخدام رمز حماية Webhook.
- الإرسال الصادر للنصوص والصور والصوت والفيديو والموقع مهيأ في `apps/api/src/providers.ts`. يمكن للموظف رفع الصور والصوت والفيديو وملفات PDF/Office/TXT (حتى 12 ميجابايت للملف) أو تسجيل رسالة صوتية. تُخزّن الملفات في PostgreSQL وتُقدّم عبر روابط موقعة؛ يتطلب الإرسال الفعلي عنوان API عامًا عبر `API_PUBLIC_URL`. تحويل التسجيلات الصوتية إلى Voice Notes يتطلب `ffmpeg`؛ صورة Docker تثبّته تلقائيًا.
- رسائل WhatsApp الصادرة تمر عبر قائمة BullMQ بمحدد معدل وتأخير قصير. تظل ردود Messenger وإرسال المنتجات عبر Messenger مقفلة بعد نافذة Meta ذات 24 ساعة؛ لا تُطبق هذه النافذة على WhatsApp أو Telegram.
- تبدأ قائمة الخدمة على أول رسالة في المحادثة، وتبقى الخيارات قابلة للتعديل من لوحة المدير. اختيار الفروع يعرض معلوماتها ويبقي العميل في القائمة؛ الخيارات الأخرى تحوّل إلى فريقها ثم تترك متابعة المحادثة للموظف.
- نموذج المنتجات التجريبي يعبأ عبر `prisma/seed.ts`؛ استبدل الصور والأسعار التجريبية ببيانات العلامة من لوحة «كتالوج المنتجات». يمكن تحميل صورة المنتج أو استخدام رابط HTTPS عام.
- يمكن للمدير إضافة المنتجات وتعديل الاسم والقسم والسعر والوصف والصورة، أو إيقاف توفر الصنف. تُرسل تفاصيل المنتج والصورة كرسالتين لضمان وصول الاسم والسعر والوصف حتى إن لم تدعم القناة تعليق الصورة.
- عند اختيار «تم الحل»، يرسل النظام استبيان 1–5 ويحفظ الرد النصي الوارد في المحادثة (بالأرقام العربية أو اللاتينية). إشعار مراحل الطلب يستخدم القناة الأصلية؛ Messenger لا يتلقى إشعارًا خارج نافذته.
- تفريغ الرسائل الصوتية اختياري: اضبط `OPENAI_API_KEY`، ويُرسل النظام الصوت الوارد (حتى 25 MB) إلى نموذج `OPENAI_TRANSCRIPTION_MODEL` الافتراضي `whisper-1`. لا يُفعّل التفريغ عند ترك المفتاح فارغًا.
- بيانات دخول KalemlyWA وMeta وTelegram، عنوان HTTPS العام، الأسرار وإعدادات الأعمال يجب أن توفرها إدارة العلامة. لا يحتوي هذا المشروع على مفاتيح حقيقية.

## ما يتضمنه النموذج

- تسجيل دخول JWT، أدوار مدير النظام وقائد الفريق والموظف ومستخدم الفرع، وصلاحيات فردية لعرض المحادثات وتحويلها وإدارة الكتالوج والتقارير والفريق.
- استعادة كلمة المرور لجميع الأدوار عبر طلب باسم المستخدم أو البريد، وموافقة مدير النظام أو تأكيد المالك من البريد الموحد `mahmoudsalamagsm@gmail.com`، ثم رابط تغيير لمرة واحدة لمدة 30 دقيقة. يتطلب الإرسال إعداد `RESEND_API_KEY` و`EMAIL_FROM` وعنوان `WEB_ORIGIN` الصحيح.
- إدارة المقر وموظفي العمل من المنزل والفروع الثمانية بأسماء قابلة للتعديل، مع توزيع Round-Robin صارم على الموظفين المتاحين.
- حضور الموظف وتسجيل جلسات العمل، شاشة إشراف مباشرة، طابور انتظار، تنبيه SLA بعد 5 دقائق، تنبيه صوتي اختياري للرسائل الواردة، ومزامنة بعد عودة اتصال Socket.IO.
- همسات المدير وملاحظات ورسائل سرية بين الزملاء لا تُرسل لقنوات العملاء؛ تصل تنبيهات الرسالة السرية للمرسل والمستلم والإدارة، وتبقى ضمن سجل المحادثة للموظفين المخوّلين. كما تتوفر تحويلات المحادثات بين موظفي خدمة العملاء، وسجل تدقيق، وردود جاهزة، وتسجيل تفاصيل طلب التورتة/التوصيل. صور العميل تبقى ضمن سجل المحادثة ولا تُربط بقالب الطلب. مساحة الموظف تفصل المحادثات النشطة والمحلولة والمؤرشفة، وتعرض وسوم الخدمة ومحادثات SLA المتجاوزة لكل موظف.
- يستقبل النظام الرسائل المتكررة بأمان عبر معرّف الرسالة الفريد، ويحافظ على فصل رسالة الموظف عن الملاحظة السرية.
- إيقاف الحساب أو إعادة كلمة المرور يبطل رموز الجلسات القديمة؛ ويعيد توجيه المحادثات المفتوحة عند تعطيل الموظف.
- محرك WhatsApp عبر QR مع API احتياطي اختياري، وإشعار/رفض المكالمات الواردة مع رد نصي، قائمة المنتجات بصورها وأسعارها وإرسال حتى 12 منتجًا معًا، مراحل الطلب بالجنيه المصري، وصور العميل محفوظة في سجل المحادثة مع أمر تحضير قابل للطباعة/الحفظ PDF.
- توجيه مبدئي تفاعلي قابل للتهيئة حسب القسم، تقييم CSAT بعد الحل مع تنبيه فوري للتقييمات الأقل من 3، وخطاف تفريغ صوت اختياري.
- تطبيق ويب قابل للتثبيت مع Service Worker وإشعارات Push اختيارية؛ يخزّن Service Worker الأصول الثابتة فقط ولا يخزّن صفحات التطبيق أو استجابات API. يلزم إعداد مفاتيح VAPID وإذن الإشعارات في المتصفح لتفعيل Push.

## ملاحظات نشر مهمة

### إعداد الاتصال الصوتي داخل النظام

للمكالمات الصادرة استخدم رقم الشركة الإيرلندي على WhatsApp Business Cloud API، وليس QR/Baileys أو تطبيق WhatsApp Business. اضبط `WHATSAPP_CLOUD_PHONE_NUMBER_ID` و`WHATSAPP_CLOUD_ACCESS_TOKEN` و`WHATSAPP_CLOUD_API_VERSION` على خدمة API. سجّل `https://<api-domain>/webhooks/meta` كـCallback لدى Meta، وضع `WHATSAPP_CLOUD_VERIFY_TOKEN` المطابق، واستخدم `WHATSAPP_CLOUD_APP_SECRET` إذا كان تطبيق Calling مختلفًا عن تطبيق Messenger. اشترك تطبيق Meta في حقلي `calls` و`messages` لحساب WhatsApp Business. يجب تفعيل Calling والامتثال لمتطلبات الحساب الحالية، ومنها حد إرسال يومي لا يقل عن 2,000 مستلم فريد؛ كما يجب أن يوافق العميل على طلب الإذن قبل بدء المكالمة. طلب الإذن الحر يحتاج نافذة محادثة مفتوحة في Cloud API؛ خارجها اضبط اسم ولغة قالب معتمد يحتوي مكوّن `call_permission_request`. رقم مصر لا يدعم مكالمات الأعمال الصادرة حسب قائمة Meta الحالية.

### نشر Railway

أنشئ خدمات PostgreSQL وRedis، ثم خدمتي API وWeb من مجلدَي `apps/api` و`apps/web` (لكل منهما `railway.json`). اضبط API على `DATABASE_URL` و`REDIS_URL` من الخدمات المرتبطة، وولّد قيمًا قوية لـ `JWT_SECRET` و`KALEMLYWA_CONFIG_ENCRYPTION_KEY` و`KALEMLYWA_WEBHOOK_SECRET` و`MEDIA_SIGNING_SECRET`. لربط WhatsApp عبر Baileys، أضف Volume دائمًا لخدمة API واربطه على `/data` قبل مسح QR؛ من دون ذلك قد تفقد الجلسة عند إعادة النشر. اضبط `API_PUBLIC_URL` إلى عنوان HTTPS العام لخدمة API حتى يستطيع مزود القناة تحميل الوسائط. استخدام Baileys يتجنب اعتماد إرسال الرسائل على مفاتيح API مدفوعة، لكنه لا يجعل الاستضافة أو التخزين أو نقل البيانات مجانية؛ راجع تكلفة خطة الاستضافة. بعد النشر، انسخ رابط Webhook الكامل الذي تعرضه لوحة المدير إلى KalemlyWA فقط إذا اخترت وضع API الاحتياطي. يمكن إدخال أسرار Meta وTelegram من إعدادات القنوات في لوحة المدير؛ وتظل متغيرات `META_*` و`TELEGRAM_*` بدائل اختيارية. عيّن `BONDOQ_ADMIN_PASSWORD` و`BONDOQ_AGENT_PASSWORD` قبل أول تشغيل إنتاجي؛ وإلا سيفشل seed بدل إنشاء كلمات مرور تجريبية معروفة. اضبط `WEB_ORIGIN` إلى نطاق Web، و`NEXT_PUBLIC_API_URL` إلى نطاق API أثناء بناء Web. لتفعيل استعادة كلمات المرور لجميع الحسابات، أضف `RESEND_API_KEY` ومُرسلًا موثّقًا في `EMAIL_FROM` على خدمة API، واضبط `PASSWORD_RESET_RECOVERY_EMAIL` على صندوق الاستعادة المركزي. يستطيع المدير الموافقة من اللوحة، أو يؤكد مالك صندوق الاستعادة الطلب عبر رابط مؤقت في البريد، ما يسمح للمدير الوحيد باستعادة حسابه. سجّل `https://<api-domain>/webhooks/meta` لدى Meta؛ ويمكن للوحة Telegram تسجيل Webhook تلقائيًا.

هذا مشروع تأسيسي يحتاج مراجعة أمنية وتشغيلية قبل خدمة العملاء الفعلية. استخدم HTTPS، أسرارًا فريدة قوية، نسخًا احتياطيًا للبيانات، تخزينًا دائمًا مناسبًا، مراقبة للأخطاء، وسياسة احتفاظ للبيانات. واجهة المتصفح تحفظ JWT في `localStorage` لتسهيل النموذج؛ عند النشر المؤسسي استبدل ذلك بملفات تعريف ارتباط `HttpOnly` آمنة، وأضف تحديد المعدل، تدوير/إبطال الجلسات، وإدارة الأسرار. كما يلزم اختبار كل قناة بحساب Business حقيقي قبل الاعتماد.
